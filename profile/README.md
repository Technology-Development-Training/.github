## 🧭 What we do

| | Domain | What it covers | Pipeline |
|:-:|:--|:--|:--|
| ⚙️ | **Software Production Automation** | Code generation, agent pipelines, template systems and CI that turn a spec into a shipped artifact. | `intent → generator → review → release` |
| 📣 | **Social Content** | Engines that create, schedule and distribute content at scale — generation and publishing in one loop. | `idea → engine → schedule → publish` |
| 🎬 | **Multimedia App** | Apps that create, process and understand media — imaging, video and audio on desktop and mobile. | `capture → process → deliver` |
| 🎮 | **Game** | Interactive entertainment: game systems, the content pipeline behind them, and player-facing experiences. | `systems → content → build → ship` |

> [!TIP]
> The through-line is the same in all four domains: **anything done twice by hand becomes a tool the third time.**

## 🧱 How we build

- ⚙️ **Automation is the product, not the cleanup.** If a step is repeated, it gets scripted, templated or generated.
- 🔁 **Reproducible beats clever.** A build you can repeat is worth more than a build you have to remember.
- 🎯 **One baseline, four outputs.** Shared tooling, shared review, shared release discipline — the domain changes, the standard does not.
- 🎓 **Training is part of shipping.** The harness, the templates and the docs are how the standard travels to the next person.
